# 兼容性：SnowLink 能做什么、做不到什么

这一页把「顶替 SnowLuma」具体化：哪些动作真能用、哪些明确不支持、返回什么。
**做不到的一律 `retcode: 1404` + `wording` 说原因**，不会返回假的成功。

## 一、动作（API）

### 能用

| 动作 | 说明 |
|---|---|
| `send_private_msg` | 发私聊。`message` 支持段数组和 CQ 字符串，`auto_escape` 也支持 |
| `send_group_msg` | 发群聊 |
| `send_msg` | 按 `message_type` 或 `user_id` / `group_id` 自动分派 |
| `get_login_info` | `user_id` / `nickname`，来自 ArkLink 的 `/api/v1/self` |
| `get_status` | `online` / `good`，附 ArkLink 的原始状态 |
| `get_version_info` | `app_name: SnowLink`、`app_version`、`protocol_version: v11` |
| `get_friend_list` | 好友列表（ArkLink `/friends`） |
| `get_group_list` | 群列表（ArkLink `/groups`） |
| `get_group_info` | 从群列表里查单个群 |
| `get_msg` | 本次运行内收到的消息（内存缓存最近 500 条） |
| `can_send_image` / `can_send_record` | 返回 `{"yes": false}`——这是**诚实的 false** |
| `get_capabilities` | 扩展动作：透传 ArkLink 的能力矩阵 |

### 明确不支持（1404 + 原因）

| 动作 | 原因 |
|---|---|
| `delete_msg` | 通道还不能撤回消息 |
| `get_group_member_info` / `get_group_member_list` | 花名册还没接真实 QQ |
| `get_stranger_info` | 没有陌生人资料接口 |
| `set_group_ban` / `set_group_kick` / `set_group_card` / `set_group_name` | 群管理通道没落地 |
| `set_friend_add_request` / `set_group_add_request` | 请求处理没落地 |
| `send_like` | 点赞没实现 |
| `get_cookies` / `get_csrf_token` / `get_credentials` | 不持有 QQ 登录凭据（在 ArkLink 侧） |
| `get_image` / `get_record` | 不接管媒体文件 |
| 群文件相关（`upload_group_file` 等） | 没落地 |
| `set_restart` | 重启交给 systemd / `start.bat`，不由本进程做 |

未知动作返回 1404，`wording` 里会列出当前支持的动作名，不会静默。

## 二、消息段

| 段 | 发送 | 接收 |
|---|---|---|
| `text` | ✅ | ✅ |
| `image` / `face` / `record` / `video` / `file` | ❌ 1404 | ⚠️ 只以文本形式呈现（ArkLink 目前只给文本） |
| `at` / `reply` / `forward` / `node` | ❌ 1404 | ⚠️ 同上 |
| `json` / `xml` / `markdown` 卡片 | ❌ 1404 | ⚠️ 同上 |

判定是**按整条消息**做的：只要有一个段发不出去，整条就失败并说明是哪些段，
不会降级成 `[图片]` 发出去骗调用方。

要发纯文本里带 `[CQ:...]` 的字面量，用 `"auto_escape": true`。

## 三、事件

| 事件 | 状态 |
|---|---|
| `message` / `private` | ✅ 来自 ArkLink 的 SSE 流 |
| `message` / `group` | ✅ 同上 |
| `message_sent` | ✅（把该连接的 `reportSelfMessage` 设为 `true` 才推） |
| `meta_event` / `lifecycle` | ✅ 连接建立时推 `connect` |
| `meta_event` / `heartbeat` | ✅ 每 15 秒 |
| `notice`（群文件、入群、撤回…） | ❌ 暂未产出 |
| `request`（加好友、加群） | ❌ 暂未产出 |

收到的事件里除了 OneBot 标准字段，还会多一个 `snowlink` 对象
（`seq` / `peer_uid` / `sender_uid` / `source`），排查问题时很有用，不认识可以忽略。

## 四、鉴权

三种写法都支持，任选其一：

```
Authorization: Bearer <accessToken>
?access_token=<accessToken>
Sec-WebSocket-Protocol: <accessToken>
```

`accessToken` 留空表示不校验——**别在公网地址上留空**。

## 五、与 SnowLuma 的差异清单

1. **不注入 QQ 进程**：QQ 由 ArkLink 那边操作，所以不需要在 Windows 上注入 DLL，
   Linux/服务器上也能跑（ArkLink 的 Xvfb 方案）。
2. **富媒体暂缺**：这是当下最大的差异，能力矩阵里写明了原因与「需要什么」。
3. **没有进程注入页**：WebUI 只有状态/网络/发送/调试/事件/日志/配置，
   不做「探测登录、加载进程」那套（那是注入方案才需要的）。
4. **多账号**：配置文件按 `onebot_<uin>.json` 一份一个账号与 SnowLuma 一致，
   但一个进程当前只跑一个账号（多实例 = 多个进程 + 不同端口）。
5. **`mode` / `statusCommand` / `historySync` / `notifications`**：
   原样读写保留，暂未实现其行为（写了不会报错，但也不产生效果）。
